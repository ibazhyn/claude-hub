# Claude Hub Starter

Готовая папка-оркестратор для **Claude Desktop → Code**: вы надиктовываете задачи (хоть десять сразу), хаб
раскладывает их на отдельные сессии, выполняет каждую в свежем контексте, проверяет независимым QA и чинит.
Он не привязан ни к проекту, ни к стеку — всё о ваших проектах узнаёт при первом запуске из `context/`.

## Быстрый старт

1. **Распакуйте** архив в любое место **вне** других проектов, например `C:\ClaudeHub` или `~/ClaudeHub`.
   Не кладите хаб внутрь репозитория или папки, где выше лежит чужой `CLAUDE.md`: Claude подхватывает
   `CLAUDE.md` из родительских папок, и правила смешаются.
2. **Положите в `context/`** `.md`-файлы о своих проектах: что за продукт, архитектура, правила, что нельзя
   ломать, как тестировать, какие есть окружения. Сколько угодно файлов, любые темы — подробности в
   `context/README.md`. Можно и позже.
3. **Claude Desktop → Code → Local →** выберите эту папку. Модель — самую сильную из доступных. Режим
   разрешений — **Auto**: исполнители и проверяющие работают в фоне и не могут сами спросить разрешение.
   Если Auto недоступен, выберите **Accept edits** — тогда хаб запускает их по одному на переднем плане, и
   Claude будет спрашивать у вас подтверждение команд.
4. **Напишите «Привет»** (или сразу задачу — она не потеряется). Хаб спросит, какие у вас репозитории и где
   они лежат. Ответьте одним сообщением:
   ```
   api — C:\Projects\shop-api — бэкенд магазина
   web — C:\Projects\shop-web — фронтенд
   ```
   Хаб зарегистрирует репозитории, один раз прочитает `context/`, составит профиль проекта (`project/`) и
   подключит защитные хуки. Claude может один раз попросить подтвердить запись настроек — подтвердите.
5. Когда он скажет, что настройка закончена, **откройте новую сессию** в этой папке и напишите «продолжай»
   (или сразу новую задачу): там загрузятся хуки и доступ к репозиториям, а задачи из первого сообщения
   запустятся сами. Дальше просто надиктовывайте задачи — хоть десять за раз.

## Примеры сообщений

| сообщение | что будет |
|---|---|
| «В корзине итог округляется неправильно, должно быть до копеек» | одна задача → одна сессия → исправление, тест, коммит, QA |
| «Три вещи: 1) … 2) … 3) …» | три отдельные сессии, каждая в своём чистом контексте |
| «статус» | что сделано, что идёт, что в очереди, что ждёт вас |
| «обнови контекст» | перечитать новые и изменённые файлы в `context/` |
| «добавь репозиторий admin, путь C:\Projects\shop-admin» | регистрация ещё одного репозитория |
| «с этого момента всегда пиши тест до исправления» | постоянное правило → `project/OVERRIDES.md` |
| «продолжай» | продолжить с того места, где остановилась прошлая сессия |

## Что происходит внутри

- Каждая проблема сразу записывается дословно в `control/INBOX.md` — до любого анализа.
- Главная сессия — только оркестратор: она раскладывает работу на сессии (`tasks/`) и сама код не пишет.
- Каждую сессию выполняет свежий исполнитель: план → правка → тесты → один локальный коммит → отчёт (`results/`).
- Независимый проверяющий сверяет каждый критерий приёмки с реальным diff и тестами; провал — автоматический ремонт.
- Всё важное хранится в файлах (`control/`, `project/`), поэтому новая сессия ничего не теряет.
- Когда контекст разрастается, хаб громко пишет вверху ответа, что нужна новая сессия, и даёт готовый промпт.

## Чего хаб никогда не делает

- Не пушит без вашей просьбы и никогда не делает force-push.
- Не переписывает историю: никаких reset, rebase, amend, stash, clean.
- Не коммитит от чужого имени — только от git-идентичности вашей машины.
- Не выдумывает данные и не выдаёт заглушки за настоящие.
- Не теряет запросы: строка в INBOX закрывается только после проверки или вашей отмены.
- Не трогает чужие незакоммиченные изменения в репозитории.

## Память

- **Файлы хаба** — главная память: `control/` (INBOX, цели, промпт для следующей сессии, решения) и
  `project/` (профиль, инварианты, соглашения, ваши правила, накопленные знания о репозиториях).
- **Встроенная память Claude** (auto memory) включена в `.claude/settings.json`.
- **Плагин claude-mem** — по желанию. Это сторонний плагин (не от Anthropic): добавляет поиск по прошлым
  сессиям, но и свои хуки. Если хотите: в Claude Code выполните `/plugin`, добавьте маркетплейс плагина
  (`thedotmack/claude-mem`) и установите `claude-mem`, сверившись с его README. Хаб сам заметит плагин и
  будет сначала спрашивать память, потом читать файлы.

## Требования

- Claude Desktop с вкладкой Code (или Claude Code).
- Git.
- Python 3.8+ — рекомендуется. Без Python хаб работает, но без защитных хуков и без `tools/hub.py`
  (статус, идентификаторы, сравнение контекста). Установить можно в любой момент и сказать «перенастрой».
- Работает на Windows и macOS/Linux.

## Если что-то не так

| симптом | что делать |
|---|---|
| Claude часто спрашивает разрешения | включите режим Auto; запись настроек при первой настройке подтвердите один раз |
| исполнители в фоне останавливаются на запросах разрешений | это не режим Auto — включите его; до тех пор хаб запускает исполнителей на переднем плане |
| у модели окно контекста 1M | скажите «у меня окно контекста 1M» — хаб поднимет пороги (или сделает это сам, когда сессия перейдёт 200k) |
| хуки не срабатывают | папка должна быть **доверенной**: при первом открытии Claude спрашивает, доверяете ли вы ей, — подтвердите; в недоверенной папке правила разрешений и хуки проекта игнорируются. Затем откройте новую сессию — хуки загружаются при старте; проверьте, что Python установлен; скажите «перенастрой» |
| нет доступа к репозиторию | откройте новую сессию — доступ к папкам тоже загружается при старте |
| хаб заблокировал команду | так задумано: в причине написано, как сделать безопасно |
| контекст слишком длинный | хаб сам скажет вверху ответа «нужна новая сессия» и даст промпт — откройте новую сессию и вставьте его (или скажите «продолжай») |
| на Windows «python» открывает Microsoft Store | установите Python с python.org; хаб сам найдёт `py -3` |

## Обновление хаба

Когда появится новая версия, **движок** можно заменить целиком:
`CLAUDE.md`, `.claude/agents/`, `.claude/skills/`, `.claude/hooks/`, `.claude/settings.json`,
`orchestration/`, `tools/`, `README.md`, `README.ru.md`.

**Состояние** нужно сохранить — это ваши данные:
`project/`, `control/`, `tasks/`, `results/`, `context/`, `archive/`, `.claude/settings.local.json`.

После обновления откройте новую сессию.

## English (short)

A ready-made orchestration hub for Claude Desktop → Code. Unzip it anywhere outside other projects, drop
Markdown files about your projects into `context/`, select the folder in Claude Desktop → Code → Local
(strongest model, Auto permission mode — background workers cannot ask for permission), and say hello. The
hub asks once for your repositories (name — absolute path, one per line), ingests `context/` into
`project/`, wires its safety hooks, and asks you to open a new session and write "continue" — tasks from
your first message then start by themselves. From then on, dictate tasks in any language, many at once: each becomes an INBOX row,
a Session with its own fresh worker, a local commit, an independent QA pass and automatic repair. It never
pushes unless asked, never rewrites history, never commits as someone else, never fabricates data and never
loses a request. Requirements: Claude Desktop with Code, Git, Python 3.8+ recommended. Updating: replace the
engine (`CLAUDE.md`, `.claude/agents`, `.claude/skills`, `.claude/hooks`, `.claude/settings.json`,
`orchestration/`, `tools/`, `README.md`, `README.ru.md`); keep the state (`project/`, `control/`, `tasks/`, `results/`,
`context/`, `archive/`, `.claude/settings.local.json`).
